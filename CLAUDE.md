# Equity Watchlist: working notes

Personal Indian-equity research app: Node ESM server (`server.mjs`, per-user data via AsyncLocalStorage) and plain browser scripts in `public/` (one global scope, loaded in `index.html` order). Every user's data stays private to their login.

## Before every release (each improvement)
1. `npm run lint` (undefined names in server and browser code).
2. `npm test` (unit + server tests).
3. `npm run perf`: starts the server on a throw-away account with outside sites (NSE, Yahoo, Screener, AMFI, Stooq, Anthropic) **hanging**, times every page's API (cold and repeat p95), static files and the live stream, and fails on a broken budget or a >50% regression against `scripts/perf-baseline.json`. When a slower number is expected and accepted, refresh the baseline with `npm run perf -- --update` and say so in the release notes.
   `npm run check` runs all three, then the mobile check.
4. New screens: add their GET API to `PAGES` in `scripts/perf.mjs` and their view name to `VIEWS` in `scripts/mobile.mjs`.
5. `npm run mobile` (`scripts/mobile.mjs`, Playwright): every screen in `VIEWS` × Android / iOS sizes in `DEVICES` (280 px to tablets, landscape); fails on sideways scroll, anything past the right edge outside a scrolling box, script errors, text boxes under 16px on iOS, tap targets under 24 px, dialogs that don't fit. Add new screens to `VIEWS`. The throw-away server for both checks is `scripts/testserver.mjs`.

## Performance rules
- A page request never waits on an outside site. Answer from cache / saved data and refresh in the background; wait (with a short budget, ~1.5 s) only the first time something was never fetched, and never repeat a failed fetch on every request (remember the try).
- Static files are compressed and cached in memory at start (`static.mjs`): restart the server to see CSS/JS edits.
- Heavy libraries load on demand (e.g. `pdfjs-dist` only when a PDF is imported).
- New screens load on demand: list them in `LAZY_VIEWS` (app.js), put their script in `public/<name>.js` (not in index.html) and their styles in `public/screens.css`. The first page load (scripts + styles in index.html) must stay under the 900 KB compressed budget.

## Privacy rules
- Per-user files only through `userFile()`; shared public caches live in `DATA_DIR` root.
- The mutual fund X-ray library (`mf-xray.json`, `U.fundsFile`) is shared by every account (fund portfolios are public data); write it only inside `withXrayLock()`. Which funds a user holds, values and links stay in their own files.
- Secrets (broker sessions, Telegram, the Anthropic key `ai-key.json`) are excluded from backups (`BACKUP_SECRET_FILES`) and never sent to the browser.
- Ask AI (`ai.mjs`): only `buildContext()` output and tool results go to the AI provider the user picked (Anthropic or an OpenAI-compatible one); never account labels / client IDs / PAN / email / folio numbers. Provider keys live in `ai-key.json` / `ai-keys.json` (secret files).
- Side-menu arrangement (`navorder.js`, `/api/ui/menu`, `menu.json`) is per login. New menu buttons need an `id` and `class="viewTab"`; they land in their default group for users who already arranged the menu.
- FIRE planner (`fire.mjs`, `/api/fire`, `fire.json`) is per login and, like expenses and buckets, never goes to Ask AI.
- `decide.mjs` is the Ask AI hold-or-sell helper; the "What to do now" screen is `nowcall.mjs` + `public/decide.js` (`/api/decide`). Check a module name is free before creating one.
- Combined P&L (`pnl.mjs`, `/api/tax/pnl`, `public/pnl.js` lazy-loaded from tax.js) reads the per-user `tradebook.json`; holder names per account in `tax-holders.json`. `tax.mjs` `fifo()` is per account (`t.account`) and splits same-day buy+sell as intraday. Dhan trades come from read-only `GET /v2/trades` (path params go in `query` so the route allow-list still matches).
- Trades are also picked up daily (`captureBrokerTrades()`, weekdays after 15:45 IST): Kite MCP `get_trades` (today only; ISIN resolved from the scrip master) and Dhan's last week. `mergeTrades()` dedupes by `tradeId` per account first, then by identical rows.
- Broker tax P&L reports (`taxreport.mjs`: Zerodha Console xlsx, INDmoney consolidated xlsx) are stored per user in `tax-reports.json` without PAN, name or folio (PAN → `panKey` hash only). `pnlView()` uses a report's rows for its account up to `to`, computed FIFO after; `dedupeReports()` drops MF rows that an all-brokers report (INDmoney) also has.
- Tax shown anywhere (Swing's tax strip / exemption left, holdings clean-up) comes from `brokerTaxNow()` (combined P&L, memoised 60 s per login in `pnlPage()`; any POST to `/api/tax` or a trade capture drops it), never from the hand-typed swing journal. `swingrecon.mjs` + `/api/swing/recon` match the journal to broker sales; fixes move the journal to the broker's numbers.
- Swing book (`swingbook.mjs`, `/api/swingbook`, `public/swingbook.js`, view `swingbook`) is built only from broker data (pnlPage trades + tradebook FIFO lots); hand-added trades go into `tradebook.json` with `src: "manual"`. The old Swing trading screen (`swing.json`) is kept until it is retired; only its Swing income tracker reads broker trades too (`brokerSwingClosed()`: Swing book closed rows of this FY and the last, 12 months; `settings.incomeSource` brokers | journal, default journal (the journal knows which sales were swing trades and their dates; Dhan reports have no dates), which also drives Booked profit via `brokerBooked()` in GET /api/swing: `booked` from broker rows of every FY, `bookedRecon` = Tax view by month split swing / longTerm / funds / other / undated).
- Diwali Muhurat picks (`muhurat.mjs`, `/api/muhurat`, `public/muhurat.js`, view `muhurat`, per-login `muhurat.json`) are hand-entered long-term holds; their symbols are in `activeSymbols()`, the price refresh and `eodUniverse()`. Never sent to Ask AI.
- Dividends received (`divledger.mjs`, `/api/divledger`, `public/divledger.js` lazy-loaded from the Dividend planner's "Received" tab, per-login `dividend-ledger.json`): hand-recorded or pasted credits by month; never sent to Ask AI.
  Auto-added credits (`autoCredits()`): holdings × announced dividends (`allDividends` → `dividendsReceived`) from `auto.from`, credited `CREDIT_LAG_DAYS` after the ex-date, ids `auto:SYM:exDate`; confirming writes a normal entry with `fromAuto`, hiding adds to `dismissed`. Never sent to Ask AI.
  Tax: `fyDividends()` (FY Apr–Mar, grossed up ÷0.9 above `divTdsThreshold`, autos already gross) feeds `pnlView({ divLedger, divHolder })`; ledger replaces report dividends for that holder (`tax-holders.json` `divHolder`, op `/api/tax/div-holder`). `divLedgerData(false)` never switches auto-add on. Any divledger POST drops the P&L memo.
- Kite MCP login (`kite-mcp.mjs`): on HTTP 401 `login({ redirectUri })` returns the OAuth `authUrl` (createOAuth from `mcp-client.mjs`, imported lazily to avoid a cycle); the browser returns to `/api/kite/callback`, the slot that owns the `state` finishes it. Tokens per slot in `kite-oauth[-slot].json` (secret file, in `SECRET_FILE_RE`, `BACKUP_SECRET_FILES`); `forget()` clears them. Test with `test/v5752-kite-oauth.test.mjs` (the sandbox cannot reach mcp.kite.trade). Tool names are resolved per job from tools/list (`KITE_OPS`, `resolveKiteOp()`, `callOp()`): legacy `get_*` names, else the hosted server's grouped tools (session / portfolio / market / mutual_funds / orders + an action enum); only read-only actions resolve. New Kite calls go through `callOp`, never a hard-coded tool name. The grouped server may not name the user: `profile()` can return null, so use `kiteIdentity(kc, slotId)` in server.mjs (reuses the account synced on that slot, else `ZERODHA-<slot>`; `{ guess: false }` for trades). `/api/kite/callback` is the one API route that answers without an app session (private-window sign-in for a second Zerodha account; owner found by OAuth state across `auth.listUsers()` in `kiteOAuthCallback()`); `syncKiteSlot()` refuses a slot whose live login (profile id, else live holdings) equals another connected slot's, and drops stale identical copies stored under other slots; never compare against stored data to block.
- Trade desk (`tradedesk.mjs` pure: `marketRegime`, `openRisk`, `checkTrade`, `edgeReport`; `/api/desk`, `public/desk.js` lazy view `desk`; per-login `desk.json` settings and `desk-compare.json` = last all-setups backtest + `tags` per closed trade). `deskContext()` reads only saved data (swing scan cache for regime/breadth, Swing book rows of every FY, journal stops); `startDeskCompare()` is the only part that fetches bars (background job per user, `backtestAll` + `compareSetups` + `entryTags` in backtest.mjs). Never sent to Ask AI. New swing setups go in `SETUP_INFO` + `detectSetups` (then they are backtested and compared automatically); the first-load budget is nearly used up (898 of 900 KB), so new UI goes in lazy scripts and `screens.css`.
- Net worth per person: `byPerson()` / `ownerName()` in networth.mjs (empty / self / me → "Me", names matched without case); synced stock and MF lines take their owner from `tax-holders.json` holders.

## Phones and web views
- Mobile fixes go in `public/mobile.css`: `(max-width:699px)` for phone layout, `(pointer:coarse)` for every touch screen (16px fields, finger-sized controls), `(pointer:coarse) and (max-height:500px) and (orientation:landscape)` for phones on their side.
- `static.mjs` `cssCompat()` adds fallbacks when it serves CSS (color-mix → the main colour, dvh/svh → vh, -webkit-backdrop-filter). Script helpers for older web views (`.at`, `Object.hasOwn`, `findLast`, `structuredClone`) are inline at the top of index.html. Support target: iOS 15+, Android WebView / Chrome 90+. Avoid regex lookbehind (`(?<=`, `(?<!`) in browser code: it breaks the whole script on iOS before 16.4.
